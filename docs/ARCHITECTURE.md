# 구조와 데이터 흐름

앱에는 서버가 없다. 모든 파싱·계산이 브라우저 안에서 끝나고, 상태는 localStorage 한 곳에 있다.

## 데이터 흐름

```
카드 명세서 ──► csv.ts ──────┐
 (CSV/xlsx/HTML)  xlsx.ts    │
                  htmltable.ts
                             ├──► Txn[] ──► detect.ts ──► DetectedSeries[] ──┐
Gmail / JSON ──► gmail.ts ───┤                                               │
                 email.ts ───┘                                               │
                 naverpay.ts                                                 ▼
                                                                    사용자 확인
                                                                             │
                                                                             ▼
                                            Subscription[] ──► money.ts ──► Totals
                                                    │
                                                    └────────► analyze.ts ──► Finding[]
```

`DetectedSeries` 는 **후보**일 뿐이다. 사용자가 확인하기 전에는 `Subscription` 이 되지 않는다.
탐지가 틀릴 수 있다는 전제가 이 경계의 이유다.

## 모듈 경계

| 파일 | 책임 | 하지 않는 것 |
|---|---|---|
| `types.ts` | 공용 타입. 모든 모듈이 여기에 의존한다 | 로직 없음 (`categoriesOf` 만 예외) |
| `normalize.ts` | 가맹점명 정규화, 알려진 서비스 사전 | 금액·날짜를 보지 않는다 |
| `csv.ts` | 파일 형식·인코딩 판별, 컬럼 매핑 추측 | 정기결제 판단을 하지 않는다 |
| `xlsx.ts` / `htmltable.ts` | 엑셀·HTML 표를 셀 격자로 | 헤더를 정하지 않는다 (`gridToTable` 담당) |
| `gemini.ts` | 사전에 없는 가맹점 이름 판독 | 등록을 대신 하지 않는다 |
| `detect.ts` | 거래 배열에서 반복 패턴을 찾는다 | 통화 환산을 하지 않는다 |
| `email.ts` / `naverpay.ts` | 영수증 메일 → 시리즈 | 네트워크를 만지지 않는다 |
| `gmail.ts` | OAuth + 메일 가져오기 | 파싱하지 않는다 |
| `fx.ts` | 결제 시점 환율 조회 | 환산 계산은 `money.ts` 가 한다 |
| `money.ts` | 주기·통화 환산, 합계 | 진단하지 않는다 |
| `analyze.ts` | 중복·낭비 진단 | 상태를 바꾸지 않는다 |
| `store.ts` | localStorage 영속화, JSON 내보내기/가져오기 | 계산하지 않는다 |

## 왜 이렇게 되어 있나 (되돌리기 쉬운 결정들)

**파일 형식은 확장자가 아니라 내용으로 본다.** 국내 카드사의 "엑셀 다운로드"가 주는 `.xls` 는
진짜 엑셀이 아니라 `<table>` 이 든 HTML 인 경우가 아주 흔하다. 확장자로 갈래를 타면 그걸 놓친다.

**EUC-KR 를 먼저 의심한다.** 국내 카드사 CSV 는 UTF-8 인 경우가 드물다.
`csv.ts` 는 UTF-8 을 fatal 모드로 먼저 시도하고, 깨지면 EUC-KR 로 넘어간다.

**환율은 통화마다 따로 조회한다.** 기준통화 하나로 묶어 받고 역수를 취하면 요청 수는 줄지만,
API 가 반올림해 주는 소수(0.00074 같은) 때문에 1350 원짜리 환율이 1351 원으로 어긋난다.
27 만원짜리 결제에서 200 원이 틀어지는 오차다.

**간격 규칙성은 MAD(중앙값 절대편차)로 잰다.** 최대 편차로 재면 예전 요금제에서 넘어온
한 번의 긴 공백 때문에 멀쩡한 월 구독의 확신도가 30% 로 떨어진다.

**구독은 카테고리를 여러 개 가진다.** Google One 은 저장소이면서 Gemini(AI)를 포함한다.
카테고리가 하나뿐이면 중복 진단이 한쪽으로 새어나간다. 중복 진단은 반드시 `categoriesOf()` 를 쓴다.

**영수증이 안 오는 결제 수단이 있다.** 통신사 결합·번들·기프트카드로 결제되면 결제 메일이 없다.
`billingChannel` 이 `CHANNELS_WITHOUT_RECEIPTS` 에 들면 "결제 끊김" 진단을 내지 않는다.
멀쩡히 쓰고 있는 구독을 좀비로 표시하는 게 반대 실수보다 나쁘다.

**네이버페이는 결제대행이다.** 발신 도메인만 보면 전부 "네이버 멤버십"이 된다.
진짜 서비스명은 본문 표 안에 있고, 12 개월치 800 건 대부분은 편의점·식당 오프라인 결제라 버려야 한다.

## 개인정보 취급

- Gmail 권한은 `gmail.readonly` 하나뿐. 액세스 토큰은 `sessionStorage` 에만 둔다
- 메일 스니펫은 300 자로 자르고 인증번호·카드번호 형태 문자열을 마스킹한다
- 카드번호는 뒷 4 자리만 저장한다
- 외부로 나가는 요청은 환율 조회(통화 코드 + 날짜)와 Google API 호출뿐이다
- 저장소에 데이터 파일을 두지 않는다. 테스트 픽스처도 실행 시점에 생성한다
