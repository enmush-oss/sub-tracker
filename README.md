# 구독 트래커 (sub-tracker)

구독 서비스 전용 가계부. 내가 뭘 구독하고 있는지, 얼마 나가는지, 뭐가 겹치는지,
**그리고 내가 잊고 있던 구독이 뭔지** 한 화면에서 본다.

데이터는 전부 브라우저 localStorage 에만 저장된다. 자체 서버가 없다.
카드 명세서·영수증 메일은 브라우저 안에서만 파싱되고 어디로도 전송되지 않는다.

외부로 나가는 요청은 세 가지뿐이다.
- **환율 조회** — 통화 코드와 날짜만 Frankfurter(ECB 공시환율)로 보낸다. 구독 내역·금액은 안 보낸다
- **Gmail 연동** — 켰을 때만. 읽기 전용 권한으로 Google API 를 직접 호출한다
- **AI 판독** — 눌렀을 때만. 사전에 없는 **가맹점 이름만** Gemini 로 보낸다. 금액·날짜·카드번호는 안 보낸다

## 실행

Node 18 이상이 필요하다 (`node -v` 로 확인).

```bash
npm install
```

```bash
npm run dev
```

`npm run dev` 는 개발 서버를 띄우고 **브라우저를 자동으로 연다** (http://localhost:5273).
안 열리면 그 주소를 직접 열면 된다.

받은 직후에는 **아무 데이터도 없는 빈 상태**다. 샘플 데이터도, 남의 결제 내역도 들어있지 않다.
대시보드의 "명세서 올리고 시작하기" 버튼에서 카드 명세서 CSV 를 넣는 것으로 시작한다.

정적 파일로 뽑아 쓰려면:

```bash
npm run build
```

## 화면 4개

| 탭 | 하는 일 |
|---|---|
| **대시보드** | 월 합계 / 연 환산 / 활성 구독 수 / 절약 가능액, 카테고리별 비중, 다가오는 결제, **점검 결과** |
| **구독** | 등록·수정·삭제. 서비스마다 `요금제(plan)` 를 따로 두어 같은 서비스의 여러 모델을 구분 |
| **자료입력** | 카드 명세서(CSV·엑셀) 또는 이메일 영수증에서 정기결제 패턴을 자동 탐지 → **미등록 결제를 "잊고 있던 구독"으로 표시** |
| **설정** | 기준통화, 좀비 판정 기간, AI 판독기 키, JSON 내보내기/가져오기 |

점검을 따로 두지 않은 이유: 진단만 보는 탭이 있으면 거기까지 안 간다.
돈이 얼마 나가는지 보러 온 화면에 "이건 겹칩니다"가 같이 있어야 실제로 읽힌다.

명세서와 이메일을 한 탭에 둔 이유: 둘은 "구독 근거를 어디서 가져올까"라는
같은 질문의 두 답이다. 갈라놓으면 처음 쓰는 사람은 어디서 시작할지 모른다.

## 핵심: 잊은 구독 찾기

수동 입력만으로는 잊은 구독을 절대 못 찾는다. 그래서 명세서 임포트가 이 앱의 중심이다.

1. 카드사 홈페이지/앱에서 이용대금명세서를 CSV 로 내려받는다
2. **명세서** 탭에 드래그앤드롭
3. 컬럼 매핑을 확인한다 (한국어 헤더는 자동 추측됨)
4. 같은 가맹점에서 일정한 간격·금액으로 반복된 결제가 정기결제 후보로 뜬다
5. 등록부에 없는 건 `잊고 있던 구독?` 배지가 붙는다 → [등록] 또는 [무시]

### 한국 카드사 CSV 대응

- **EUC-KR(CP949) 인코딩 자동 판별.** 국내 카드사 CSV 는 대부분 UTF-8 이 아니다
- 상단 안내문 잡줄(`○○카드 이용대금명세서` 등) 자동 스킵
- 한국어 헤더 자동 인식: `이용일자` `가맹점명` `이용금액` `승인일` `적요` 등
- 날짜 형식: `2025.03.14` `2025-03-14` `25/03/14` `20250314` `2025년 3월 14일`
- 금액 형식: `12,900` `12,900원` `-12,900` `(12,900)`

## 이메일 자동수집

카드 명세서에는 "GOOGLE *Google One" 같은 가맹점명만 찍힌다. 요금제도, 다음 갱신일도,
연간 결제인지도 안 나온다. 그 정보는 영수증 메일에만 있다. 그래서 수집 경로를 하나 더 뒀다.

**이메일** 탭에 세 가지 경로가 있다.

1. **Gmail 직접 연동** — 앱이 직접 메일을 읽는다. 읽기 전용(`gmail.readonly`) 권한만 쓰고,
   액세스 토큰은 `sessionStorage` 에만 둬서 브라우저를 닫으면 사라진다.
   Google Cloud Console 에서 OAuth 클라이언트 ID(웹)를 만들어 **설정**에 넣어야 한다
   (승인된 자바스크립트 원본에 `http://localhost:5273` 추가).
2. **JSON 붙여넣기** — Claude 에게 Gmail 을 훑게 하고 그 결과를 붙여넣는다. 설정이 필요 없다.
3. **메일 원문 붙여넣기** — 영수증 메일 하나를 통째로 붙여넣으면 파싱한다.

세 경로 모두 `EmailReceipt` 로 수렴한 뒤 `DetectedSeries` 로 변환되어,
CSV 명세서와 **완전히 같은** 진단 파이프라인을 탄다.

### 메일에서 뽑아내는 것

- 금액: `₩17,000` `17,000원` `$9.99` `USD 9.99` — 소계·부가세가 같이 있으면 총액을 고른다
- 주기: `월 14,900원` `매월` `연간` `monthly` `$100/year` `6개월` 등
- 다음 결제일: `다음 결제일 2026-10-14` `2026년 10월 14일에 갱신` `renews on Oct 14, 2026`
- 종류: 결제완료 / 갱신예정 / 체험종료 / 가입 / **해지** / 요금인상

해지 메일이 온 서비스는 시리즈에서 통째로 뺀다. 이미 끊은 걸 "잊은 구독"이라 부르면 안 된다.

### 결제대행(네이버페이 등)으로 낸 구독

네이버페이·PayPal 같은 대행사가 보낸 영수증은 발신 도메인만 보면 **대행사 이름으로
오분류된다**. 실제 서비스명은 본문 안에 있다. 그래서 대행사별 전용 파서를 둔다.

네이버페이의 경우:
- `결제처` 가 PG사(NICE정보통신 등)면 진짜 서비스명은 `상품정보` 쪽에 있다
- **오프라인 결제는 통째로 버린다.** 편의점·식당 결제가 12개월에 800건 넘게 오는데,
  안 거르면 정기결제 탐지가 그걸로 뒤덮인다
- **주문 취소 안내를 구독 해지로 읽지 않는다.** 물건 반품 하나 때문에 멀쩡한 구독이
  시리즈에서 사라지면 안 된다
- `자동결제 등록내역` 제목은 정기결제의 직접 증거로 취급한다

### 메일만 잡아낼 수 있는 것들

- **연간·다년 약정** — 2년 약정 VPN 처럼 최근 12개월 명세서에 결제가 한 번도 안 찍히는 구독.
  본문에 주기 단어가 없어도 갱신일까지의 간격으로 주기를 역산한다
- **요금제 변경** — 같은 서비스의 금액이 바뀌면 중앙값이 아니라 **가장 최근 결제 금액**을 쓴다.
  앞으로 나갈 돈은 그거니까. 금액이 바뀌었다고 확신도를 깎지도 않는다(간격이 고르면 구독이다)
- **통화** — USD 구독을 원화로 뭉개지 않는다. `$220/년` 은 `$220.00 · 연간` 으로 표시되고
  기준통화 합계에는 환율로 환산해서 들어간다

### 개인정보

- 메일 본문은 저장하지 않는다. 근거 스니펫 300자까지만 남긴다
- 인증코드·카드번호로 보이는 문자열은 스니펫에서 마스킹한다
- `data/gmail-receipts.json` 은 `.gitignore` 에 있어 커밋되지 않는다
- 메일 내용은 어디로도 전송되지 않는다. Gmail 연동을 켰을 때만 Google API 를 직접 호출한다

## 겹침 진단 방식

두 축으로 본다.

1. **같은 카테고리 중복** — OTT 3개, 음악 2개처럼 같은 용도가 여러 개
2. **기능 겹침** — 카테고리가 달라도 실제로 겹치는 것.
   예: YouTube Premium(동영상 플랫폼) 과 Spotify(음악) 는 둘 다 음악 스트리밍이다

**같은 구독 묶음이 두 축에 다 걸리면 하나만 보고한다.** 기능 겹침이 카테고리 중복의
부분집합이면 지운다. 같은 얘기를 두 번 하면 목록만 길어지고 신뢰를 잃는다.

### 대체재가 아닌 것을 묶지 않는다

- **OTT 와 동영상 플랫폼은 다른 카테고리다.** YouTube Premium 은 넷플릭스의 대체재가
  아니다. 한 카테고리로 묶으면 "둘 중 하나 정리하라"는 성립하지 않는 조언이 나온다
- **요금제까지 본다.** YouTube Premium 은 YouTube Music 을 포함하지만 **Lite 요금제는
  빠진다.** 서비스 이름만 보고 묶으면 없는 겹침을 만들어낸다

### 절약 가능액

두 숫자를 같이 낸다. 하나만 내면 오해를 부른다.

- **보수적 값** — 가장 싼 것 하나만 정리. 상단 합계에 쓰는 안전한 수치
- **상한** — 제일 싼 것 하나만 남기고 나머지 정리

월 27만원짜리와 월 7,500원짜리가 겹칠 때 "7,500원 아낍니다"라고만 하면 정작 중요한
사실을 숨기는 셈이다. 진단 정렬도 **상한 기준**으로 한다. 그러지 않으면 월 30만원짜리
중복이 월 2만원짜리 밑으로 밀린다.

## 통화 — 결제 시점 환율 자동 적용

USD 구독과 KRW 구독을 같이 봐도 기준통화(기본 KRW)로 통합 환산된다.
환율은 **자동으로** 조회한다. 손으로 넣은 숫자는 틀리기 때문이다 — 실제로 1,380 으로 박아뒀다가
$220 구독 하나에서 2만원 넘게 틀어졌다.

- 출처: 유럽중앙은행(ECB) 공시환율 · [Frankfurter](https://api.frankfurter.dev)
- **과거 결제는 그 결제일의 환율**로 환산한다. 예: 2026-07-13 USD/KRW = 1,494.09
- **앞으로 나갈 돈은 최신 환율**로 추정한다
- 주말·공휴일 결제는 직전 영업일 환율을 쓴다
- 조회 실패 시 **설정** 탭의 수동 환율로 자동 폴백한다. 오프라인에서도 앱은 계속 동작한다
- 받아온 환율은 저장해두고 재사용한다 (과거 환율은 바뀌지 않으므로)

## 명세서·메일에 안 잡히는 결제

통신사 결합(KT 등), 번들, 기프트카드로 내는 구독은 카드 명세서에도 서비스 영수증 메일에도
안 찍힌다. 그래서 구독마다 **결제 경로**를 지정할 수 있다.

`card` 가 아닌 경로로 표시하면 "결제 끊김" 오진을 하지 않는다.
멀쩡히 돈 나가는 구독을 끊겼다고 하는 게 이 앱에서 가장 나쁜 오류다.

## 넣을 수 있는 파일

| 형식 | 비고 |
|---|---|
| `.csv` | 구분자(`,` `;` 탭 `\|`) 자동 추정. UTF-8 / EUC-KR 자동 판별 |
| `.xlsx` | 첫 시트를 읽는다. 날짜 서식 셀은 일련번호가 아니라 날짜로 변환 |
| `.xls` (HTML 표) | 국내 카드사 "엑셀 다운로드"가 주는 실제 형식. 표가 여러 개면 행이 가장 많은 걸 고른다 |
| `.xls` (구형 BIFF) | **못 읽는다.** 엑셀에서 열어 `.xlsx` 나 CSV 로 다시 저장하라고 안내한다 |

확장자가 아니라 **파일 내용**으로 구분한다. `.xls` 라는 이름이 붙었다고 엑셀인 경우가
오히려 드물기 때문이다.

xlsx 는 zip 안에 든 XML 이라 브라우저 내장 `DecompressionStream` 으로 직접 읽는다.
라이브러리를 붙이지 않았다 — 번들이 두 배가 되고, SheetJS 의 npm 배포판은
오래 방치돼 알려진 취약점이 남아 있다.

## AI 판독기 (선택)

`PADDLE.NET* SETAPP` 이나 `NICE정보통신(주) OPENAI` 같은 표기는 규칙 기반 사전으로는 못 읽는다.
명세서 탭에서 **사전에 없는 가맹점만** 골라 Gemini 에게 물어볼 수 있다.

- [Google AI Studio](https://aistudio.google.com/apikey) 에서 무료 키를 받아 **설정 탭**에 넣는다
- 나가는 건 가맹점 문자열뿐이다. 금액·날짜·카드번호·거래 건수는 보내지 않는다
- 기본은 꺼져 있다. 키를 넣고 버튼을 눌러야만 호출된다
- 판독 결과는 참고용이다. 등록 전에 서비스명·카테고리를 직접 확인해라

로컬에서 키를 매번 넣기 싫으면 프로젝트 루트에 `.dev.vars` 를 두면 된다 (`.gitignore` 에 있다):

```
GOOGLE_CLIENT_ID=...   # Gmail 연동용 (implicit flow — 공개돼도 되는 값)
GEMINI_API_KEY=...     # AI 판독기용
```

`vite.config.ts` 는 **이 두 키만** 화이트리스트로 읽는다.
`GOOGLE_CLIENT_SECRET` 같은 건 목록에 없으므로 번들에 들어가지 않는다.
다만 화이트리스트에 든 값은 빌드 결과물에 평문으로 박히므로, **남에게 배포할 빌드라면
`.dev.vars` 를 비우고** 사용자가 설정 탭에서 직접 넣게 해라.

## 증거가 없는 구독은 앱이 정하지 않는다

계정 메일(약관 변경, 비밀번호 안내)은 오는데 결제 영수증이 없는 서비스가 있다.
통신사 결합이나 기프트카드로 내면 정상적으로 이렇게 된다 — **진짜 쓰고 있는데 증거만 없는 것**이다.
반대로 예전에 해지했는데 마케팅 메일만 남은 것일 수도 있다.

앱은 둘을 구분할 수 없다. 그래서 지우지도, 금액을 지어내 등록하지도 않는다.
점검 탭에 "○○ 를 구독 중인가요?"로 올리고 사용자가 정한다.

- **구독 중이에요** → 구독 폼이 열린다. 금액·주기는 비어 있다. 없는 숫자를 채워 넣으면
  그 값이 그대로 월 합계에 들어가기 때문이다
- **아니에요** → `dismissedCandidates` 에 기록한다.
  **이게 없으면 메일을 다시 스캔할 때마다 지운 항목이 되살아난다.**

다시 스캔해도 중복으로 뜨지 않는 이유는 세 가지를 함께 보기 때문이다 —
이미 등록된 구독(`merchantPatterns` 포함), 결제 시리즈가 잡힌 서비스,
사용자가 정리한 목록. 비교는 표기가 아니라 정규화 키로 한다
(`Netflix` 와 `NETFLIX` 가 따로 뜨면 안 된다).

## 한 구독이 여러 용도를 겸할 때

카테고리를 하나만 두면 중복 진단이 새어나간다.
Google One 은 저장소지만 Gemini(AI)를 포함하므로, 저장소 중복과 AI 중복 **양쪽에** 잡혀야 한다.
그래서 주 카테고리 외에 **부가 카테고리**를 여러 개 붙일 수 있다.

## 저장소에 데이터 파일이 없는 이유

명세서 픽스처를 커밋해두면 (1) 남의 소비 내역처럼 보이고 (2) 날짜가 박제돼 시간이 지나면
전부 "결제 끊김"으로 잡혀 테스트가 무의미해진다.
그래서 테스트용 명세서는 `src/lib/__tests__/helpers/statement.ts` 가 **실행 시점에 메모리에서**
만든다 (오늘 기준 상대 날짜, EUC-KR 인코딩 포함).

  types.ts            공용 타입 계약

    normalize.ts      가맹점명 정규화 + 알려진 서비스 사전

    detect.ts         정기결제 시리즈 탐지
    email.ts          영수증 메일 파싱 → 시리즈 변환
    naverpay.ts       네이버페이 결제 메일 전용 파서
    fx.ts             결제 시점 환율 자동 조회
    gemini.ts         AI 판독기 — 사전에 없는 가맹점 이름 해석
    gmail.ts          Gmail OAuth + API (읽기 전용)

    store.ts          localStorage 영속화
  components/         화면 4개

data/                 내보낸 개인 데이터를 두는 곳 (커밋 안 됨)
